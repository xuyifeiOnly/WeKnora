# 如棠智能知识库 · Linux 线上部署指南

基于 Docker Compose 的服务器部署手册。适用于已安装 Docker 的 Linux 服务器。

---

## 一、部署前必读

> ⚠️ **本项目前端已做品牌定制**（如棠科技 logo、名称、文案）。
> 官方镜像 `wechatopenai/weknora-ui` 不含这些改动，**前端镜像必须自行构建**。
> 后端（app / docreader）未改动，可直接使用官方镜像。

因此部署流程中，`frontend` 服务必须执行 `docker compose build frontend`，
不能只做 `docker compose pull`，否则页面上仍会显示 WeKnora 默认品牌。

**另外：本地改动需要先提交并推送到你自己的仓库**，服务器才能拉到：

```bash
# 本地（你的开发机）
git add -A && git commit -m "品牌定制：如棠科技"
git push origin main
```

## 二、服务器要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux x86_64 或 arm64（CentOS 7+ / Ubuntu 20.04+ / Debian 11+） |
| CPU / 内存 | **建议 4 核 8GB 起**（docreader 镜像含大量解析依赖，内存不足会 OOM） |
| 磁盘 | **建议 50GB+**（镜像约 8GB，另有数据卷持续增长） |
| Docker | 20.10+ |
| Docker Compose | **v2**（`docker compose` 子命令；v1 的 `docker-compose` 也可用） |

检查环境：

```bash
docker version
docker compose version
```

### 需要开放的端口

| 端口 | 用途 | 是否必须对外 |
|------|------|--------------|
| `80` | Web 界面（FRONTEND_PORT，可改） | ✅ 必须 |
| `8080` | 后端 API（APP_PORT，可改） | 建议仅内网（走 80 反代） |

> 其余服务（postgres / redis / docreader）默认**不映射到宿主机**，只在容器网络内互通，无需开放。

### 放行防火墙

```bash
# firewalld（CentOS / RHEL）
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload

# ufw（Ubuntu / Debian）
sudo ufw allow 80/tcp
sudo ufw allow 8080/tcp
```

## 四、配置 .env

```bash
cd /opt/weknora
cp .env.example .env
```

### 4.1 生成密钥（必做）

```bash
openssl rand -hex 32   # → JWT_SECRET
openssl rand -hex 16   # → SYSTEM_AES_KEY（必须是 32 字节）
openssl rand -hex 32   # → SYSTEM_SIGNING_KEY（可选）
```

### 4.2 必须修改的配置项

编辑 `vim .env`：

| 变量 | 建议值 | 说明 |
|------|--------|------|
| `DB_PASSWORD` | 强密码 | ⚠️ 务必改掉默认 `postgres123!@#` |
| `REDIS_PASSWORD` | 强密码 | ⚠️ 务必改掉默认 `redis123!@#` |
| `JWT_SECRET` | 上一步生成 | 登录令牌签名密钥 |
| `SYSTEM_AES_KEY` | 上一步生成 | **32 字节**，加密数据库中的 API Key。**丢失则已加密数据无法恢复** |
| `SYSTEM_SIGNING_KEY` | 上一步生成 | 可选，留空则回退用 SYSTEM_AES_KEY |
| `FRONTEND_PORT` | `80` | 被占用时改（如 `8081`） |
| `APP_PORT` | `8080` | 后端对宿主机端口 |
| `TZ` | `Asia/Shanghai` | 时区 |
| `WEKNORA_LANGUAGE` | `zh-CN` | 问题/摘要生成语言 |
| `WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL` | 管理员邮箱 | 把该邮箱账号提权为系统管理员，详见 **4.4 节** |
| `DISABLE_REGISTRATION` | 初始化管理员后改 `true` | 关闭公开注册，详见 **4.4 节** |

### 4.3 国内服务器建议开启（加速构建）

```ini
# npm 源（构建前端用，镜像已在容器内，不影响宿主机）
NPM_REGISTRY=https://registry.npmmirror.com
# Alpine apk 源（构建 app 镜像用）
APK_MIRROR_ARG=mirrors.tencent.com
```

### 4.4 关闭注册与初始化管理员

#### 机制说明（重要）

WeKnora **没有**"用环境变量直接预置管理员账号密码"的机制，需要先理解这两项配置：

| 配置 | 实际作用 |
|------|----------|
| `DISABLE_REGISTRATION=true` | 关闭公开注册：拦截 `POST /api/v1/auth/register`，前端登录页的注册入口会自动隐藏（通过 `GET /auth/config` 获知） |
| `WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL` | 仅把**已存在**的该邮箱用户提权为系统管理员。**不建号、不含密码**，且只在 **app 启动时**、且**当前系统管理员数为 0** 时执行一次 |

所以"部署时得到一个能直接登录的管理员"需要三步：
**创建账号 → 重启触发提权 → 关闭注册**。

#### 方式一：使用脚本（推荐）

```bash
cd /opt/weknora

# 参数：<邮箱> <用户名> <密码>
./scripts/init-admin.sh admin@rutang.cn admin 'Rutang@2026'
```

脚本会自动完成：等待服务就绪 → 注册账号 → 写入 bootstrap 邮箱并重启 app → 校验提权结果。
成功后按提示关闭注册：

```ini
# .env
DISABLE_REGISTRATION=true
```

```bash
docker compose up -d app
```

> 脚本是幂等的，重复执行不会重复建号。
> 若提示"注册功能已关闭"，先把 `DISABLE_REGISTRATION` 临时改回 `false`
> 并 `docker compose up -d app`，再重跑脚本，完成后记得改回 `true`。

#### 方式二：手动执行

```bash
# 1) .env 中先保持注册开启，并设置 bootstrap 邮箱
#    DISABLE_REGISTRATION=false
#    WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=admin@rutang.cn
docker compose up -d

# 2) 注册账号（密码换成你自己的）
curl -X POST http://127.0.0.1:8080/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","email":"admin@rutang.cn","password":"Rutang@2026"}'

# 3) 重启 app 触发提权（环境变量变更会自动重建容器）
docker compose up -d app

# 4) 校验：is_system_admin 应为 t
docker compose exec postgres psql -U postgres -d WeKnora \
  -c "SELECT email, is_system_admin FROM users WHERE email='admin@rutang.cn';"

# 5) 关闭注册
sed -i 's|^[[:space:]]*#*[[:space:]]*DISABLE_REGISTRATION=.*|DISABLE_REGISTRATION=true|' .env
docker compose up -d app
```

#### 之后：管理员创建其他用户

关闭注册**不影响**管理员建号。管理员登录后有两种方式：

**A. 界面操作**（推荐）

「设置 → 系统管理 → 创建用户」，填写用户名 / 邮箱 / 密码。
不填密码时系统会生成一次性随机密码，且只显示一次。

**B. 调用接口**

```bash
curl -X POST http://127.0.0.1:8080/api/v1/system/admin/users/create \
  -H "Authorization: Bearer <管理员Token>" \
  -H 'Content-Type: application/json' \
  -d '{"username":"zhangsan","email":"zhangsan@rutang.cn","password":"Abcd@1234"}'
```

其他相关接口（均需系统管理员权限）：

| 接口 | 用途 |
|------|------|
| `POST /api/v1/system/admin/users/create` | 创建用户（可指定密码，省略则生成随机密码） |
| `POST /api/v1/system/admin/users/reset-password` | 重置指定邮箱用户的密码（会撤销其所有会话） |
| `POST /api/v1/system/admin/promote` | 提权某用户为系统管理员 |
| `POST /api/v1/system/admin/revoke` | 撤销系统管理员 |

> 这些接口**不走注册网关**，因此 `DISABLE_REGISTRATION=true` 时依然可用。
> 注意空间内"邀请成员"（`/tenants/:id/invitations`）要求对方**已注册**，
> 关闭注册后请优先用上面的「创建用户」直接建号。

### 4.5 修改运行端口

所有对外端口都在 `.env` 中通过**左侧变量**修改。
映射格式为 `宿主机端口:容器内端口`，**容器内端口固定不变**，只改宿主机侧。

| 变量 | 默认值 | 作用 |
|------|--------|------|
| `FRONTEND_PORT` | `80` | Web 界面对外端口（**最常改**） |
| `APP_PORT` | `8080` | 后端 API 对外端口 |
| `APP_BACKEND_PORT` | `8080` | 前端 nginx 转发到后端的**容器内**端口，本地单机部署**不要改** |
| `MINIO_PORT` / `MINIO_CONSOLE_PORT` | 9000 / 9001 | MinIO 对象存储（`--profile minio`） |
| `QDRANT_REST_PORT` / `QDRANT_PORT` | 6333 / 6334 | Qdrant（`--profile qdrant`） |
| `SEARXNG_PORT` | 8888 | 自建搜索（`--profile searxng`） |
| `LANGFUSE_WEB_PORT` | 3000 | Langfuse 界面（`--profile langfuse`） |
| `MCP_PORT` | 8082 | MCP Server（`--profile full`） |

**示例：Web 界面改到 9008，API 改到 18080**

```ini
FRONTEND_PORT=9008
APP_PORT=18080
```

**生效（端口映射变更需要重建容器）**

```bash
docker compose up -d        # compose 会自动 recreate 受影响的服务
docker compose ps           # 确认新端口已生效
```

之后访问地址变为 `http://<服务器IP>:9008`。

**注意事项**

- `APP_PORT` 只影响宿主机映射。前端容器是通过容器网络 `app:8080` 访问后端的，
  所以**改 `APP_PORT` 不需要动 `APP_BACKEND_PORT`**。
- 若有外层 nginx 反代，需同步修改 `proxy_pass http://127.0.0.1:<FRONTEND_PORT>;`。
- 改端口后建议同步设置绝对地址，否则邀请链接、嵌入 Widget 可能生成错误 URL。
  这两项位于 `.env` 的 **A 节末尾**（`DOCREADER_TRANSPORT` 附近），
  在 `.env.example` 中**默认被注释**，需去掉行首 `#` 再填值：

```ini
# .env 中放开注释并填写真实地址（<服务器IP> 为占位符，有域名则填域名）
FRONTEND_BASE_URL=http://192.168.1.100:9008
APP_EXTERNAL_URL=http://192.168.1.100:18080
```

  两者的用途并不相同：

  | 变量 | 用途 | 何时需要 |
  |------|------|----------|
  | `FRONTEND_BASE_URL` | 邀请链接等页面绝对 URL | 改端口 / 用域名时建议设置 |
  | `APP_EXTERNAL_URL` | IM 渠道（企微/飞书/Slack）图片文件外链 | **仅在使用 IM 集成时**需要 |

  `APP_EXTERNAL_URL` 走的是 `<APP_EXTERNAL_URL>/r/<token>`，**需要外层 nginx 额外代理 `/r/` 路径**，
  否则图片无法显示：

```nginx
location /r/ {
    proxy_pass http://127.0.0.1:<FRONTEND_PORT>;
    proxy_set_header Host $host;
}
```

  两项留空时回退为相对路径，内网同域名访问不受影响。
  修改后执行 `docker compose up -d app` 重建 app 容器，
  用 `docker compose exec app env | grep -E 'FRONTEND_BASE_URL|APP_EXTERNAL_URL'` 确认已注入。

- 记得在防火墙放行新端口；被占用报 `address already in use` 时，
  用 `ss -lntp | grep <端口>` 或 `lsof -i:<端口>` 查看占用进程。

## 五、构建与启动

```bash
cd /opt/weknora

# 1. 拉取基础镜像（postgres / redis / app / docreader）
docker compose pull

# 2. 构建定制前端镜像（必须执行，否则品牌不生效）
docker compose build frontend

# 3. 启动全部服务
docker compose up -d
```

> ⚠️ 顺序很重要：`pull` 会拉取官方 `weknora-ui` 覆盖同名标签，
> 所以**必须在 pull 之后再 build frontend**。
> 后续不要再单独执行 `docker compose pull frontend`。

### 需要附加组件时（可选 Profile）

```bash
# 知识图谱
docker compose --profile neo4j pull && docker compose --profile neo4j up -d
# 对象存储
docker compose --profile minio up -d
# 全部组件
docker compose --profile full up -d
```

## 七、配置域名与 HTTPS（推荐）

前端容器已内置 nginx，直接在**宿主机**再挂一层 nginx 做 TLS 即可。

安装 nginx 与证书工具：

```bash
sudo apt install -y nginx certbot python3-certbot-nginx   # Debian/Ubuntu
```

`/etc/nginx/conf.d/weknora.conf`：

```nginx
server {
    listen 80;
    server_name kb.yourcompany.com;

    # 大文件上传（按需调整，需与 .env 的 MAX_FILE_SIZE_MB 配合）
    client_max_body_size 200m;

    location / {
        proxy_pass http://127.0.0.1:80;          # FRONTEND_PORT
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 流式问答 / 沙箱终端需要 WebSocket
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 长耗时请求（文档解析、Agent 推理）
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

签发证书并重载：

```bash
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d kb.yourcompany.com
```

> 启用 HTTPS 后，若需要 IM 渠道回传图片等外链，请在 `.env` 中设置
> `APP_EXTERNAL_URL=https://kb.yourcompany.com` 与 `FRONTEND_BASE_URL=https://kb.yourcompany.com`。

## 八、日常运维

### 8.1 常用命令

```bash
cd /opt/weknora

docker compose ps                      # 状态
docker compose logs -f app             # 后端日志
docker compose logs -f --tail=100 frontend
docker compose restart app             # 重启单个服务
docker compose stop                    # 停止（保留数据）
docker compose down                    # 停止并删除容器（数据卷保留）
docker compose down -v                 # ⚠️ 连数据卷一起删除，数据不可恢复
```

### 8.2 数据备份

数据分两部分：**数据库**（postgres 卷）和**上传文件**（data-files 卷）。

```bash
# 1) 数据库导出（推荐每日定时）
docker compose exec -T postgres pg_dump -U postgres WeKnora > backup_$(date +%F).sql

# 2) 上传文件打包
docker run --rm \
  -v weknora_data-files:/data:ro \
  -v "$(pwd)":/backup \
  alpine tar czf /backup/files_$(date +%F).tar.gz -C /data .

# 3) 恢复
cat backup_2026-09-20.sql | docker compose exec -T postgres psql -U postgres -d WeKnora
docker run --rm -v weknora_data-files:/data -v "$(pwd)":/backup \
  alpine sh -c 'tar xzf /backup/files_2026-09-20.tar.gz -C /data'
```

> 卷名前缀默认取自目录名（`/opt/weknora` → `weknora_`）。
> 用 `docker volume ls` 确认实际卷名。

### 8.3 升级

```bash
cd /opt/weknora
git pull                               # 拉取最新源码（含新的品牌/功能改动）

docker compose pull                    # 拉取官方镜像更新
docker compose build frontend          # 重新构建定制前端
docker compose up -d                   # 滚动替换
docker image prune -f                  # 清理旧镜像（可选）
```

### 8.4 回滚

```bash
git log --oneline -10                  # 找到目标提交
git checkout <commit-id>
docker compose build frontend
docker compose up -d
```

数据库结构升级（AUTO_MIGRATE 默认开启）通常向前兼容，回滚代码前建议先备份数据库。

### 8.5 开机自启

`docker-compose.yml` 中各服务已配置 `restart: unless-stopped`，
**只要 Docker 开机自启即可**，无需额外配置：

```bash
sudo systemctl enable docker
```

## 九、常见问题

**Q1：页面仍是 WeKnora 默认样式**
忘记构建定制前端。执行 `docker compose build frontend && docker compose up -d frontend`，
并确认拉取镜像顺序是「先 pull、后 build」。

**Q2：拉镜像很慢 / 超时**
为 Docker 配置国内镜像加速器，编辑 `/etc/docker/daemon.json`：

```json
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com", "https://docker.m.daocloud.io"]
}
```

```bash
sudo systemctl daemon-reload && sudo systemctl restart docker
```

若服务器完全无外网，改用离线方式：在能联网的机器上
`docker pull` / `docker build` 后 `docker save`，传输到服务器 `docker load`。

**Q3：容器启动后 app 反复重启 /  unhealthy**
查看日志定位：`docker compose logs app --tail=200`。
常见原因是 `DB_PASSWORD` 与已存在的数据卷密码不一致——
首次启动后修改密码不会同步到已有的 postgres 卷，需 `docker compose down -v` 重建（会丢数据）或在库内改密。

**Q4：内存不足，docreader 被 OOM Kill**
`docker inspect WeKnora-docreader | grep -i oom` 确认后，
升级服务器内存，或在 `.env` 中降低并发：

```ini
DOCREADER_GRPC_MAX_WORKERS=2
DOCREADER_PDF_RENDER_MAX_WORKERS=1
WEKNORA_ASYNQ_CORE_CONCURRENCY=4
```

**Q5：80 端口被占用**
`.env` 中改 `FRONTEND_PORT=8081`，`docker compose up -d frontend`。

**Q6：上传大文件失败**
同时调整三处：`.env` 的 `MAX_FILE_SIZE_MB`、外层 nginx 的 `client_max_body_size`、
（若启用）对象存储的限额。
